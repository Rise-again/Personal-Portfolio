---

这是我今年重复了四次的流程。目标不是"做一个产品"，而是**在七天内让一个真实的人用上它，并说出哪里难受**。

## 第 1 天：只写一句话

把想法压缩成一句可被证伪的话。写不出来就先别写代码。

```text
让 [谁] 在 [什么时候] 用 [什么] 完成 [什么]，
如果有效，[某个数字] 会变化。
```

如果这句话里有"以及"，说明你要做两个产品。

## 第 2 天：画出唯一一条路径

用纸笔画出用户从进入到拿到价值的**最短路径**。通常不超过四步。

我习惯把它写成状态机，因为写着写着就会发现有些状态根本不需要存在：

```js
const steps = ['idle', 'input', 'thinking', 'result']

function next(state, event) {
  if (state === 'idle' && event === 'start') return 'input'
  if (state === 'input' && event === 'submit') return 'thinking'
  if (state === 'thinking' && event === 'done') return 'result'
  return state
}
```

没有 `error` 状态不是疏忽，是我在第三天才会决定它长什么样。

## 第 3 天：接上模型，先跑通丑陋版本

不做流式、不做重试、不做缓存。先让它出结果。

```python
response = client.messages.create(
    model="claude-sonnet-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": prompt}],
)
```

这一步唯一的目标是：**看见它真的能work**。所有关于"体验"的讨论都应该发生在这之后。

## 第 4—5 天：只修最痛的两处

找三个人用。不要问"你觉得怎么样"，只观察三件事：

1. 他们在哪一步停顿超过 5 秒
2. 他们是否重复点击同一个按钮
3. 他们第一句话说的是什么

通常你会发现，最痛的地方和你想的完全不一样——而且往往不是模型不够聪明，而是**等待的时候屏幕上什么都没有**。

## 第 6 天：让它体面地失败

- 超时给一句人话，而不是 `Request failed`
- 结果为空时给出可执行的下一步
- 保留用户输入，别让一次失败清空他的努力

## 第 7 天：发出去

发给十个可能在意这个问题的人。附一句说明：**这是原型，不是产品。**

然后观察谁真的用了。

---

七天的意义不在于快，而在于**它强制你把假设和实现分开**。真正难的从来不是写代码，是在动手之前想清楚要证明什么。
